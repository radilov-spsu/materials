# Лабораторная работа 1 — заготовка

Стартовый проект к лабораторной [«Фабрики: простая, фабричный метод,
абстрактная»](../../labs/01-fabriki-prostaya-metod-abstraktnaya.md).
Здесь лежит **заведомо плохой код** этапа 0: вся логика создания врагов свалена
в `WaveSpawner` вместе с ветвлениями по локации.

## Как забрать себе

Скопируйте содержимое этой папки в свою работу — целиком, вместе с `tests/`:

```bash
git clone --depth 1 https://github.com/radilov-spsu/materials.git /tmp/materials
cp -r /tmp/materials/OOP/examples/GameFactories/. <ваш-репозиторий>/OOP/lab-01/
```

Без git: на [странице материалов](https://github.com/radilov-spsu/materials)
**Code → Download ZIP**, распаковать, взять папку `OOP/examples/GameFactories`.

Развёрнутая заготовка — ваш **первый коммит**, до единой собственной правки.
Тогда в истории видно, что написали вы, а что было дано.

## Как запустить

```bash
dotnet run --project src/GameFactories          # демонстрация волны
dotnet test                                     # тесты (сейчас один, ваших ещё нет)
```

Нужен .NET SDK 8.0 или новее. Если стоит только .NET 9/10, запуск всё равно
сработает:

```bash
DOTNET_ROLL_FORWARD=LatestMajor dotnet run --project src/GameFactories
DOTNET_ROLL_FORWARD=LatestMajor dotnet test
```

## Что делать

1. Прочитать задание лабораторной работы (этапы 0–4).
2. Начать с `src/GameFactories/WaveSpawner.cs` — это код этапа 0.
3. Каждый этап — **отдельный коммит** с внятным сообщением:
   `этап 1: простая фабрика`, `этап 2: фабричный метод`, и так далее.
4. Отчёт писать в этот же файл, заменив его содержимое (см. шаблон ниже).
   Тот текст, который вы сейчас читаете, в сдаче остаться не должен.

## Структура

```
src/GameFactories/
    Program.cs          точка входа: демонстрация волны
    WaveSpawner.cs      ← код этапа 0, с него начинаете
    Domain/             враги, оружие, лут — менять можно и нужно
tests/GameFactories.Tests/
    WaveSpawnerTests.cs один пример теста; остальные пишете вы
```

## Шаблон отчёта

Замените содержимое этого файла на отчёт по такой структуре:

- **Вариант** — номер и вселенная.
- **Этап 0** — сколько конкретных классов использует `WaveSpawner` сейчас; сколько станет
  после добавления третьей локации; какие части метода меняются, а какие нет.
- **Этап 1** — что изменилось в зависимостях; почему простая фабрика не паттерн.
- **Этап 2** — кто принимает решение о типе врага; зачем нужна зацепка.
- **Этап 3** — что придётся изменить при добавлении нового **вида** продукта (список файлов).
- **Этап 4** — итоговая таблица сравнения и ответ на вопрос «что оставили бы в проекте».
- **Диаграммы** — три диаграммы классов в Mermaid: «как было», фабричный метод,
  абстрактная фабрика.
- **Чем платим** — по абзацу на каждый из трёх подходов.
