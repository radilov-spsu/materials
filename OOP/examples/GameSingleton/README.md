# Лабораторная работа 4 — заготовка

Стартовый проект к лабораторной [«Одиночка: как его пишут и почему от него уходят»](../../labs/04-odinochka-i-ukhod-ot-nego.md).
Здесь лежит код этапа 0: наивный одиночка, который в многопоточной среде
создаёт несколько экземпляров.

## Как забрать себе

Скопируйте содержимое этой папки в свою работу — целиком, вместе с `tests/`:

```bash
git clone --depth 1 https://github.com/radilov-spsu/materials.git /tmp/materials
cp -r /tmp/materials/OOP/examples/GameSingleton/. <ваш-репозиторий>/OOP/lab-04/
```

Без git: на [странице материалов](https://github.com/radilov-spsu/materials)
**Code → Download ZIP**, распаковать, взять папку `OOP/examples/GameSingleton`.

Развёрнутая заготовка — ваш **первый коммит**, до единой собственной правки.
Тогда в истории видно, что написали вы, а что было дано.

## Как запустить

```bash
dotnet run --project src/GameSingleton      # демонстрация гонки
dotnet test                                 # тесты
```

Нужен .NET SDK 8.0 или новее. Если стоит только .NET 9/10, запуск всё равно
сработает:

```bash
DOTNET_ROLL_FORWARD=LatestMajor dotnet run --project src/GameSingleton
DOTNET_ROLL_FORWARD=LatestMajor dotnet test
```

## Структура

```
src/GameSingleton/
    Program.cs              демонстрация: 50 потоков берут Instance
    Domain/GameConfig.cs    ← наивный одиночка этапа 0
    Domain/EventLog.cs      журнал событий — вторая «единственная» сущность
    WaveSpawner.cs          потребитель конфигурации: лезет в Instance изнутри метода
tests/GameSingleton.Tests/
    GameConfigTests.cs      один пример; падающий многопоточный тест пишете вы
```

## Порядок работы

1. Развернуть заготовку, проверить `dotnet run` и `dotnet test` — это первый коммит.
2. **Этап 0 — отдельный коммит с падающим тестом.** Он должен остаться в истории:
   это доказательство, что проблема была.
3. Дальше по этапам, каждый — отдельный коммит.

> Подсказка к этапу 0: `Thread.Sleep` внутри геттера стоит не просто так — он расширяет
> окно гонки и делает баг воспроизводимым. Без него тест падал бы раз в тысячу запусков,
> и именно поэтому такие ошибки доживают до продакшена.

## Шаблон отчёта

- **Вариант** — номер, вселенная, набор «единственных» сущностей.
- **Этап 0** — сколько экземпляров получилось; почему число нестабильно; что было бы
  в реальной игре.
- **Этап 1** — таблица трёх реализаций: когда создаётся экземпляр, нужна ли блокировка
  при каждом чтении, что будет без `volatile`, что будет без второй проверки.
- **Этап 2** — три абзаца, по одному на проблему, со ссылками на свои падающие тесты.
- **Этап 3** — что изменилось: экземпляр по-прежнему один, почему тесты стали независимыми.
- **Этап 4** — таблица сравнения и ответ «когда одиночка оправдан» с конкретным примером.
- **Диаграмма** в Mermaid.
