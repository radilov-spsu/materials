# Лабораторная работа 6 — заготовка

Стартовый проект к лабораторной [«Мост: две иерархии вместо одной»](../../labs/06-most-dve-ierarkhii-vmesto-odnoy.md).
Здесь лежит код этапа 0: интерфейс игры сделан наследованием по двум осям,
и классов уже шесть при трёх элементах и двух способах рисования.

## Как забрать себе

Скопируйте содержимое этой папки в свою работу — целиком, вместе с `tests/`:

```bash
git clone --depth 1 https://github.com/radilov-spsu/materials.git /tmp/materials
cp -r /tmp/materials/OOP/examples/HudBridge/. <ваш-репозиторий>/OOP/lab-06/
```

Без git: на [странице материалов](https://github.com/radilov-spsu/materials)
**Code → Download ZIP**, распаковать, взять папку `OOP/examples/HudBridge`.

Развёрнутая заготовка — ваш **первый коммит**, до единой собственной правки.
Тогда в истории видно, что написали вы, а что было дано.

## Как запустить

```bash
dotnet run --project src/HudBridge      # рисует интерфейс в консоль и в SVG
dotnet test                             # тесты
```

Нужен .NET SDK 8.0 или новее. Если стоит только .NET 9/10, запуск всё равно
сработает:

```bash
DOTNET_ROLL_FORWARD=LatestMajor dotnet run --project src/HudBridge
DOTNET_ROLL_FORWARD=LatestMajor dotnet test
```

SVG сохраняется в `hud.svg` рядом с бинарником — откройте его в браузере.

## Структура

```
src/HudBridge/
    Program.cs                  точка входа: рисует интерфейс двумя способами
    Geometry/Shapes.cs          Point и Rect — пригодятся для примитивов
    Hud/HudElement.cs           ← код этапа 0: шесть классов на две оси
tests/HudBridge.Tests/
    HudTests.cs                 два примера; остальные пишете вы
```

## На что смотреть в первую очередь

Откройте `Hud/HudElement.cs` и сравните `ConsoleHealthBar.Render()` с
`SvgHealthBar.Render()`. Один и тот же расчёт заполнения полоски написан дважды.
То же с миникартой и окном диалога. Это и есть граница, по которой пройдёт мост:
**расчёт — в абстракцию, рисование — в реализацию**.

## Порядок работы

1. Скопировать папку себе и проверить `dotnet run` и `dotnet test` — первый коммит.
2. Этапы 0–1 — по коммиту.
3. **Этап 2 — два отдельных коммита**: «новый элемент интерфейса» и «новая реализация».
   К каждому приложить `git diff --stat` в отчёт: он и есть доказательство
   независимости осей.
4. Этап 3 — подмена реализации у живого объекта.

## Шаблон отчёта

- **Вариант** — номер, вселенная, три абстракции и три реализации.
- **Этап 0** — формула `N × M`, таблица роста, список дублирующегося кода.
- **Этап 1** — ваш набор примитивов с обоснованием: что отвергли как слишком мелкое
  и как слишком крупное.
- **Этап 2** — оба `git diff --stat`; если пришлось тронуть чужую иерархию — честный разбор.
- **Этап 3** — почему в версии этапа 0 так сделать нельзя.
- **Этап 4** — таблица соседей: мост, адаптер, стратегия, строитель.
- **Диаграмма** с обеими иерархиями, раздел «чем платим».
